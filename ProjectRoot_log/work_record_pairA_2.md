### 2. 已完成任务清单

#### 2.1 登录/注册集成测试 (AuthTest.java)

* 编写 `test/AuthTest.java`，对 `AuthService` 的登录与注册核心业务流进行全覆盖测试。
* 测试场景分类（共 5 个核心用例）：
    * **正常注册与登录**：验证新建用户、哈希密码生成以及正确的账号密码比对逻辑。
    * **错误密码拦截**：注册用户后，使用错误的密码尝试登录，验证系统是否正确拦截并返回空。
    * **未知用户拦截**：使用未在系统中注册的用户名进行登录，验证拦截逻辑。
    * **重复注册防范**：尝试使用已存在的用户名再次注册不同的角色，验证唯一性校验。
    * **大小写不敏感校验**：使用大写字母注册，小写字母登录，验证用户名匹配的鲁棒性。
* 使用独立的临时测试 CSV 文件 `data/test_users.csv`，确保不污染系统生成的种子数据。
* **结果**：所有断言全部通过，确认 L2 层认证与用户管理逻辑正常运行。

### 3. 关键设计决策 (Design Decisions)

| 设计点 | 决策方案 | 原因/理由 |
| :--- | :--- | :--- |
| **测试框架** | 摒弃 JUnit，自实现断言工具方法 | 保持与 L1 层相同的“零外部依赖”策略，确保项目仅通过原生 `compile.bat` 即可在任何环境中无报错编译运行。 |
| **测试隔离** | 独立数据源 `test_users.csv` | 测试环境与正式运行环境分离，在 `setUp` 和 `tearDown` 阶段动态创建与删除测试文件，防止脏数据积累。 |
| **审查重心** | 安全防御优先，UI 细节次之 | 考虑到 L2 是系统的入口（登录注册），重点排查了密码的传递方式、哈希校验逻辑以及多用户并发操作时全量 I/O 的潜在风险。 |

### 4. 遇到的问题与解决方案

#### 4.1 外部测试依赖导致编译失败
* **问题**：最初采用 JUnit 5 编写测试时，由于 VS Code 环境未统一配置依赖，导致组员本地报错 `The import org.junit cannot be resolved`。
* **解决**：重构了整个 `AuthTest.java`，将基于注解的测试改为基于 `main` 方法驱动的流程。手写了轻量级的 `assertTrue` 和 `assertEqual` 方法打印测试结果，解决了编译痛点。

#### 4.2 UI 与逻辑测试解耦
* **问题**：如果直接测试 Swing 的 `JFrame` 页面点击事件，代码复杂度极高且容易出现线程阻塞。
* **解决**：得益于 Pair B 在设计时将业务逻辑抽离到了 `AuthService`，测试组决定绕过 UI 界面，直接对 `AuthService` 接口进行单元/集成测试，极大地提升了测试的稳定性和执行效率。
